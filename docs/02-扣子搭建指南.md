# 扣子搭建指南 —— 减肥管家（照做 1~2 小时能用）

> 配套《01-需求文档.md》第 12 节分支方案。平台：**coze.cn**（扣子国内版，字节出品，手机号即可注册）。

## 0. 扣子是什么（30 秒版）

无代码 AI 智能体搭建平台：把**人设提示词 + 知识库（不忘计划）+ 数据库（记账本）+ 工作流（自动算账）+ 插件（拍照识别）**打包成一个机器人，一键发布成**网页链接**，手机浏览器打开即用。你搭的不是"聊天机器人"，是一个**有账本的管家**——这是它和直接聊豆包的本质区别。

---

## 1. 创建智能体（10 分钟）

1. 打开 coze.cn → 手机号/抖音号登录 → 「创建智能体」→ 名称：`减肥管家`
2. 模型选择：选**豆包·视觉理解（doubao-vision）**或开启"图片理解"能力（必须，否则看不了照片）
3. 把下面第 2 节的提示词整段粘贴到「人设与回复逻辑」

## 2. 人设提示词（直接粘贴）

```
# 角色
你是「减肥管家」= 管家 + 营养师 + 健身教练，服务一位减脂用户。设计三原则：
1. 一步记录：用户拍照或说一句话即完成记录，不反问表单
2. 卡片反馈：每次回复 ≤3 行
3. 不主动刷屏：用户不问就不展开长分析

# 数据规则（最重要）
- 用户档案在知识库《身体档案》里：日目标热量、蛋白目标、身高体重
- 每次记餐/记训练必须写入数据库表 meals / workouts，日期用今天
- 回答"今天吃了多少/还剩多少"必须先查数据库再计算，禁止凭聊天记忆估算

# 记餐规则
1. 收到图片：视觉识别菜品和份量 → 先查知识库《常吃食物热量表》，表里有按表算，没有再凭经验估
2. 收到文字（可能是语音转文字）：解析食物和份量 → 同上
3. 记录后固定输出：
   ✅ 已记录{餐次}：{食物}，约{热量}kcal（区间{低}~{高}）｜蛋白{X}g
   📊 今日已吃 {sum}/{目标} kcal｜蛋白 {p}/{蛋白目标}g
   🔜 剩余 {剩余} kcal
4. 识别不确定就给区间并说"可更正"；用户更正后按更正值入库

# 查询规则
「还能吃多少 / 剩多少」：查当日 meals 求和 → 目标−已吃 → 第3行给克数建议：
   例：🔜 剩余 630 ≈ 米饭150g + 瘦肉120g + 蔬菜300g
「我吃的要不要调整」：对比蛋白/热量缺口，给 1~3 条具体改法（如"晚餐加个蛋、饭减半碗"）

# 训练规则
用户报训练：解析动作/组次/时长 → 写入 workouts → 估消耗区间 → 对照知识库《训练计划》输出：
   ✅ 已记录：深蹲 4x12、弓步蹲 3x12，40分钟，消耗约 220~280 kcal
   🎯 对照本周计划：✅腿+拉已完成，今日达标 / ⚠️缺推类，明天补卧推

# 禁止
- 不编造精确数值，一律区间+依据
- 不漏入库、不写错日期
- 不输出超过 3 行的主动分析
```

## 3. 建数据库（记账本，15 分钟）

智能体编辑页 → 「数据库」→ 新建两张表：

**表 1：meals（餐食账本）**

| 字段 | 类型 | 说明 |
|---|---|---|
| date | String | 记录日期 YYYY-MM-DD |
| meal_type | String | 早/午/晚/加餐 |
| food | String | 菜品内容 |
| kcal | Integer | 热量（区间中值） |
| kcal_low / kcal_high | Integer | 区间上下限 |
| protein_g | Integer | 蛋白克数 |
| note | String | 备注/用户更正 |

**表 2：workouts（训练账本）**

| 字段 | 类型 | 说明 |
|---|---|---|
| date | String | 日期 |
| action | String | 动作内容 |
| sets_reps | String | 组数次数（如 4x12） |
| duration_min | Integer | 时长（分钟） |
| est_kcal | Integer | 估算消耗 |
| note | String | 备注 |

两张表都开启"智能体可读写"。

## 4. 传知识库（不忘计划的关键，15 分钟）

「知识库」→ 新建文本/表格知识库，上传 3 份：

1. **《身体档案》**（新建文档，填你的真实数据）：
   ```
   身高：__cm 体重：__kg 年龄：__ 性别：__
   目标：减脂，目标体重 __kg
   每日热量目标：__kcal（我可以帮你按 Mifflin-St Jeor 算）
   每日蛋白目标：__g
   每周训练：__天
   ```
2. **《训练计划》**：把你现在的 4 练计划原样贴进去（练几day/动作/组次）
3. **《常吃食物热量表》**（⭐准确度关键）：把你食堂常吃的菜逐个查一下热量（薄荷App查就行），做成表格上传：

   | 食物 | 份量 | 热量kcal | 蛋白g |
   |---|---|---|---|
   | 米饭 | 二两 | 145 | 3 |
   | 去皮鸡腿 | 1个 | 180 | 22 |
   | 鸡蛋 | 1个 | 75 | 7 |
   | 豆浆 | 250ml | 80 | 7 |
   | 清炒时蔬 | 1份 | 90 | 3 |
   | …（你的常吃清单） | | | |

   **为什么这张表是灵魂**：识别引擎"对着表查"比"凭感觉估"准一个档次，而且天天吃的菜就那几样，这张表会越来越准。

## 5. 查剩余额度工作流（可选但推荐，20 分钟）

「工作流」→ 新建 `query_remaining`：
```
开始 → 数据库查询节点（meals 表，条件 date=今天）
     → 代码节点（Python：对 kcal 列求和，目标−sum）
     → 结束（输出：今日已吃 X / 目标 Y，剩余 Z）
```
在人设提示词里声明：涉及"剩多少"的计算一律调用此工作流。这一步把"LLM 心算出错"的概率压到最低。

## 6. 发布到手机（5 分钟）

1. 右上角「发布」→ 渠道选 **「Web SDK / 获取链接」** → 复制链接
2. 手机浏览器打开该链接 → 浏览器菜单 → **「添加到主屏幕」**——以后像 App 一样点开
3. （可选）同页可发布到**豆包 App**渠道：在豆包里打开它，有**原生语音按钮**，说话更方便

## 7. 日常怎么用

| 场景 | 操作 | 你会看到 |
|---|---|---|
| 吃完饭 | 拍一张发出 | ✅已记录午餐…📊已吃/目标 🔜剩余 |
| 懒得拍/零食 | 输入法语音说"喝了一杯拿铁" | 同上 |
| 饭前 | 问"晚上还能吃多少" | 剩余热量 + 克数建议 |
| 有疑问 | 问"我吃的要不要调整" | 1~3 条具体改法 |
| 练完 | 语音说"深蹲4组12个卧推5组5个，50分钟" | 记录+消耗区间+达标判断 |
| 每周 | 问"这周怎么样" | 汇总（聊天形式） |

## 8. 已知局限（提前说清，别到时觉得被坑）

1. **界面是聊天流**：没有"今日剩余"常驻首页卡片、没有曲线图——这是和自建的核心差距
2. **算账依赖工作流**：不建第 5 节工作流的话，LLM 偶尔会算错/漏记；建了也会偶发（观察 2 周就是看这个）
3. **数据在字节平台**：数据库页可查看记录，导出 CSV 以当时界面为准（试验期记录建议每周随手导一次备份）
4. **免费额度**：个人轻度使用基本够；超了绑火山方舟按量付费也很便宜（一天几分钱级）
5. **语音**：网页版靠输入法语音转文字；要原生语音按钮就走豆包 App 渠道

## 9. 2 周试验操作（对齐需求文档 12.2）

- Day 1~3：专注养成"吃完拍一张"的肌肉记忆，别管准不准
- 第 1 周末：抽查 5 餐记录 vs 你的直觉，看识别误差
- 每天：随手看"剩余额度"和实际饭量是否对得上（验算账可靠性）
- 第 14 天：按 12.2 验收表打分 → 通过继续用 / 不通过 → 回自建（账本 CSV 迁移）
