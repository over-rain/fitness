## 1. 🔴 线上照片缩略图全部不显示（用户实测报告）

- **现象**：http://106.14.174.18/ 今日明细里，有照片的记录缩略图全是 broken image（用户截图：米饭/清汤/红烧肉等）；本地开发机同一份代码显示正常。
- **根因**：明细缩略图用 `<img src="/photo/<id>">`（app.py 内 INDEX 脚本 refresh()），**`<img>` 是浏览器原生请求，无法携带 `X-Access-Token` 请求头**。而 `/photo/` 路由开了访问码校验（`_authed()`，app.py:1248-1250）。前端只在 `api()` 的 fetch 里带 token，`<img>` 不经过它 → 线上（配置了 `access_code`）全部 404 空图；本地没设访问码 → `_authed()` 恒真，所以正常。
- **已复现**（临时端口跑生产代码，`access_code="secret123"`，record_1.jpg 真实存在）：
  - 无 token（`<img>` 的真实情况）→ `404, 0 字节`
  - 带 token（fetch 的情况）→ `200, 照片正常`
- **修法方向**（任选，均只动一处）：
  1. 前端改：缩略图用 `api()` fetch 后转 blob/data URL 再赋给 `<img src>`（改动集中在 refresh()/openEdit()）
  2. 后端改：`/photo/` 支持 `?t=<访问码>` 查询参数兜底（URL 会进日志，安全性略弱）
  3. 后端改：照片文件名带随机不可猜 token，`/photo/` 免鉴权但 URL 不可枚举（顺带解决 #3）

## 2. 🔴 运动训练被记成食物「未知」，正向计入已吃

- **现象**：发「骑车40分钟」这类训练描述，明细出现一条 `food=未知` 的记录，训练消耗的 220 千卡被**加进**「今日已吃」，剩余额度反而变少——方向完全反了。
- **根因**：提示词规则⑦让模型对训练输出 `action=training`（app.py:64-66），`workouts` 表也建了（app.py:135），但 `_handle_meal` 只处理了 `correct` 分支（app.py:1452），training 项直接掉进 `insert_meals`（app.py:1481）。训练项没有 `food`/`meal_type` 字段 → 落成 `food="未知"` 的餐食记录。
- **已复现**（生产代码 + mock 模型返回 training 项）：
  - 返回：`✅ 已记录早餐：?，约220kcal`，meals 表新增 `{food:'未知', kcal:220}`，`workouts` 表 0 条
  - 汇总：`已吃 220/2000`（应为消耗抵扣而非摄入）
- **修法方向**：`_handle_meal` 加 `action=="training"` 分支 → 写 `workouts` 表；汇总层决定消耗如何展示（从剩余额度加回或单独一行），不进食物明细。注意 `today_summary` 与 `/api/clear` 是否要覆盖 workouts。

## 3. 🟡 `/photo/<id>` 不校验记录归属用户

- **位置**：app.py:1248-1259。只校验访问码 + id 存在，不校验该记录 `user_id` 是否为当前用户。
- **影响**：两位用户共享同一访问码，改 id 即可看对方餐食照片。同 token 场景下低危，但语义越权；id 是自增整数，可枚举。
- **修法方向**：校验 `SELECT user_id FROM meals WHERE id=?`；或按 #1 修法 3 用不可猜 URL。

## 4. 🟡 编辑食物改名时，「扣回:xxx」伴生记录不跟随改名

- **位置**：`_handle_meal` 的 correct 分支有伴生改名逻辑（app.py:1467-1471），但编辑抽屉走的 `_handle_correct` edit（app.py:1499-1524）没有。
- **现象**：上午记「红烧肉」，中午通过编辑抽屉改名「回锅肉」后，若存在「扣回:红烧肉」记录，它不会变成「扣回:回锅肉」，两条记录语义脱钩。
- **修法方向**：`_handle_correct` edit 改名时复制同一段伴生 UPDATE。

## 5. 🟢 全天只有负数记录时，进度条宽度为负

- **位置**：INDEX 脚本 refresh()：`pct=Math.min(100, j.eaten/j.target*100)`，eaten 为负 → `style.width="-x%"`，CSS 不认负百分比，进度条显示异常（维持 0 或上次值）。
- **修法方向**：`pct=Math.max(0, ...)` 钳一下。

## 6. 🟢 编辑抽屉克重联动在份量无数字时静默失效

- **位置**：INDEX 脚本 openEdit()：`editBase.per=pnum(r.portion)` 只提取阿拉伯数字（如「200g」「3片」）；份量为「半份/一碗/未说明数量」时 `per=null`，改克重不联动热量/蛋白，但界面文案仍承诺「会自动按比例更新」。
- **修法方向**：`per=null` 时隐藏/改写联动提示文案，或支持「半=0.5」中文数字。
